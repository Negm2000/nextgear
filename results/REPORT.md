## 4. What if the agent had done something else?

At every decision point of the first 400 test sessions (4320 points), each model predicts the check's verdict for all ten gears and for a submission. The checks give the true answer. 39649 gear queries are actions the agent did not take; 66% of those would have been rejected.

| Model | Right verdict, untaken gears | Gear verdict log loss | P(pass) if forced to submit | Submit log loss |
|---|---:|---:|---:|---:|
| n-gram (6) | 97.04% | 0.0982 | 15.8% | 0.4467 |
| State counts | 96.03% | 0.1285 | 14.0% | 0.3627 |
| GRU | 99.87% | 0.0060 | 13.1% | 0.3675 |
| Oracle | 100.00% | 0.0000 | 12.7% | 0.2698 |
| Oracle with do() | 100.00% | 0.0000 | 9.5% | 0.1631 |

Forced submissions pass 9.3% of the time. In the logs, an agent submits when it believes the assembly is ready, so a model trained on them reads a submission as evidence of readiness and over-predicts a pass. The oracle without do() does the same, because it treats the submission as an observation. The oracle queried with do() treats the submission as forced and does not learn from it. These what-if figures are descriptive; no intervals are reported for them.

## 6. A requirement combination never seen in training

Sessions whose specification needs the Chat Engine with both the Policy Manager and the License Resolver were removed from training and validation (688 training sessions). The count models and a GRU were refit without them, then scored on 600 new sessions of exactly that kind. "GRU" is the normal model, which did see such sessions. The oracle keeps the base prior and is not told that the evaluation sessions come from this group. It is a common reference, not the best score available to a predictor that knew the group. Model settings and the n-gram context are reused from the main experiment, where they were chosen on validation data that included this group, so this is an exploratory exclusion test rather than an untouched holdout.

The intervals are conditional on the fitted models and the authored generator. They do not cover simulator misspecification or all training randomness; the three full-data training seeds show some of the latter, and the holdout GRU has a single seed. The analyses are exploratory, without preregistration or correction for multiple comparisons. The oracle shares transition code with the generator, so it is a reference inside the simulator, not independent validation of the domain assumptions.
